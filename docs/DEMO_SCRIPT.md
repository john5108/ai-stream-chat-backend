# 90 秒演示录制脚本

## 录制前准备

1. 启动服务：

   ```powershell
   cd E:\learn-fastapi\chat-backed
   ..\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
   ```

2. 浏览器打开 <http://127.0.0.1:8000/>。
3. 关闭含有 `.env`、API Key、终端历史记录的窗口。
4. 屏幕录制建议 1080p，鼠标移动放慢。

## 分镜

| 时间 | 操作 | 旁白 |
| --- | --- | --- |
| 0-10s | 展示调试页顶部和会话列表 | “这是我做的 AI 流式对话后端，前端是一个原生 HTML 调试页。” |
| 10-25s | 点击“新建”，输入“请用一句话介绍 FastAPI”，点击发送 | “后端使用 FastAPI、SQLAlchemy 和 AsyncOpenAI，聊天接口通过 SSE 返回。” |
| 25-40s | 展示消息逐段出现，等待完成 | “流式生成器内部独立管理数据库 session，流结束后一次性保存完整回复。” |
| 40-55s | 刷新页面，重新打开该会话 | “刷新后从 SQLite 重新拉取会话和历史，说明持久化链路已经打通。” |
| 55-70s | 打开 `/docs`，展开 5 个接口 | “这里可以看到创建会话、列表、历史、删除和流式聊天 5 个接口。” |
| 70-85s | 切换到终端，运行 `python smoke_test.py` | “这份冒烟测试使用假模型流，不消耗额度，覆盖会话隔离、最近 20 条上下文和级联删除。” |
| 85-90s | 回到调试页 | “下一步会在这个后端底座上做电商评论洞察或客服 Agent。” |

## 讲解重点

- 为什么用 SSE：服务端单向推送，基于 HTTP，适合 token 流式输出。
- 为什么新开数据库 session：长连接期间请求级 session 可能已经关闭。
- 为什么只取最近 20 条：控制上下文长度和 token 成本。
- 为什么先写用户消息、最后写 AI 回复：保证记录完整，避免逐 token 写库。

## 不要展示

- `.env` 文件内容
- API Key
- 终端历史里的密钥
- 未完成的本地笔记文件
